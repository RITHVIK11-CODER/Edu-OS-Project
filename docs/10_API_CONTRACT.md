# EduOS — API Contract

**Version:** 1.0  
**Purpose:** Stable contract between Frontend, Backend, and AI integration teams.

---

## 1. Contract Rule

Frontend and backend teams must treat this document as the interface boundary.

A developer must not:
- invent endpoint names;
- change response shapes casually;
- expose database internals;
- move backend business logic into UI code.

Breaking changes require explicit coordination.

---

## 2. Standard Headers

```text
Authorization: Bearer <access_token>
Content-Type: application/json
X-Request-ID: <uuid>
```

`X-Request-ID` may be generated by the client or server.

---

## 3. Standard Success Envelope

```json
{
  "success": true,
  "data": {},
  "message": "Success"
}
```

---

## 4. Standard Error Envelope

```json
{
  "success": false,
  "error": {
    "code": "ERROR_CODE",
    "message": "Human-readable message",
    "details": null
  }
}
```

```json

  "success": true,
  "data": {
```

## 13. Validation Contract

IDs must be valid UUIDs where UUIDs are used.

Strings:
- enforce maximum length;
- trim unnecessary whitespace;
- reject invalid control input.

Numeric:
- enforce sensible ranges.

---

## 14. Authentication Contract

Protected APIs require a valid authenticated token.

The server derives current user from token.

The client must not be trusted to declare:
- role;
- student ownership;
- teacher ownership.

---

## 15. AI Contract

AI is never called directly from frontend.

```text
Frontend
 ↓
FastAPI
 ↓
AI Service
 ↓
LLM
```

AI responses must pass schema validation before becoming API output.

---

## 16. Contract Change Procedure

Before changing:
1. search usages;
2. update backend;
3. update frontend;
4. update tests;
5. update this document;
6. run integration tests.

---

## 17. Frontend Implementation Rule

Frontend models should mirror API schemas.

Do not duplicate backend business logic.

Example:

Backend returns:

```json
{
  "mastery": 41,
  "status": "WEAK"
}
```

Frontend should render it, not independently recalculate mastery.

---

## 18. Contract Definition of Done

- endpoint implemented;
- schema validated;
- auth tested;
- errors documented;
- frontend integrated;
- tests passing;
- docs updated.
